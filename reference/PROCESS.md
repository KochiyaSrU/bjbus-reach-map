# 北京公交可达范围图 · 实现记录与踩坑

> 这份文档记录「北京公交 60 分钟可达范围图」在实现过程中遇到的真问题：现象、原因、怎么修。
> 站点一律用**类型**表述（城区枢纽、远郊终点、山区定班线……），因为换一个城市、换一批线路，
> 坑的形状是一样的，只有名字不同。

---

## 1. 目标与口径

给定一个公交站，在「最多换乘一次、总耗时 ≤ 60 分钟」约束下，算出所有可达站并出图。

- 总图：等时面（0–15 / 15–30 / 30–45 / 45–60 四档）+ 站点 + 片区名 + 大枢纽 + 边界站
- 核心区放大图：起点周边 4–5 km，逐站标注
- 数据：CSV / GeoJSON / Shapefile（WGS84）

**总耗时 = 候车₁ + 乘车₁ + 换乘步行 + 候车₂ + 乘车₂**

---

## 2. 数据源

公交实时数据服务（MCP over SSE）。四类接口：

| 接口 | 内容 | 备注 |
|---|---|---|
| 按站名查线路 | 某站经过的线路方向 | 用来核对站名 |
| 按线路查站序 | 站名序列 + 经纬度 + 站间距 | 坐标来自这里 |
| 按线路查时刻表 | **每班车到每站的时刻** | 乘车时间的唯一来源 |
| 按线路查班次（带日期） | 首末站发车时刻 + 服务日期 | **发车间隔的唯一可靠来源** |

算法要点：

- 乘车时间 = 同一班车相邻两站时刻差，多班次取中位数
- 发车间隔 = 按服务日分组后的平均间隔（见 4.3）
- 候车 = 分档计算（见 4.4）

---

## 3. 坐标基准：两个必须做的转换

### 3.1 公交数据是国内坐标系，底图是国际坐标系

直接把两组坐标画在一起，站点会整体偏移几百米——城市尺度上还以为是路网画歪了，
放大后才发现每个点都系统性偏同一个方向。

**自检方法**：把站点云整体平移，找让最多站点落在道路亮像素上的位移。

- 未转换：最优位移是一个明显非零的偏移
- 转换后：最优位移为 (0, 0)

**修法**：在解析线路站序时统一做一次坐标转换，下游（出图、CSV、SHP）全部用转换后的坐标。

**注意**：判断"有没有偏移"要求目标函数有对比度。在几乎没有路网的乡村裁片上，亮度函数是平的，
容易得到假的非零位移——要么用城区做自检，要么在指标里加"峰值显著性"，低于阈值就报
"无法判断"，而不是报一个偏移。

### 3.2 同名站点往往有多个坐标

同一个站名在数据里有 2–16 个不同坐标（不同港湾、上下行、历史版本），相差几十到几百米。
直接画会散成一簇点，看起来像"站点跑到街上"。

**修法**：按 260 m 单链接聚类，然后取 **medoid**（簇里真实存在的、最居中的那个观测点）。
**不要用质心**——质心可能落在两个港湾之间的地块里，图上就是"站点在马路上"。

## 4. 时间模型：三个容易做错的地方

### 4.1 缺失区段必须按距离补，不能用线路中位数

时刻表是滚动窗口，某班车可能只记录了一部分站点。

**反面案例**：某条高速快线的 61 km 高速段在窗口里没有时刻，被"用该线路其他区段的中位数"补成
3 分钟——等效车速 179 km/h，直接让 60 km 外的城市变成"半小时可达"。

**修法**：缺失段按 `距离 / 14 m·s⁻¹`（约 50 km/h）估算。

### 4.2 单区段上限不能卡太紧

过滤异常值时如果把上限设成 30 分钟，真实的高速段（1 小时以上）会被当异常删掉，
于是又回到 4.1 的错误。**上限放到 2 小时。**

### 4.3 发车间隔：必须用带日期的数据，且不能用中位数

这一条踩得最深，是三个叠加的坑：

**坑 A：时刻表没有日期列，多天数据混在一起。**
一条一天 2 班的山区线，窗口里看到 4 行记录，实际是「2 班/天 × 2 天」。
直接数行数会把班次算成 2 倍；按"首末班跨度 ÷（行数−1）"算间隔，会把间隔算成一半。

**坑 B：同一趟车会被记录两次。**
滚动窗口在相邻区段重叠，同一班车在重叠站出现两行，两行相隔 10–15 分钟。
不合并的话，这些"伪间隔"会把平均间隔拉低一半以上。

**坑 C：用中位数会掩盖中午的空白。**
车都挤在早晚高峰时，中位数只反映"最密那一段"，可能比真实平均间隔小 3–4 倍。

**修法**（按顺序做）：

1. 用**带日期**的班次接口，按服务日分组；
2. 同日内合并相差 ≤ 20 分钟的重复记录（密集线路用 2 分钟，避免把真正的 6 分钟间隔并掉）；
3. 取**平均间隔**（跨度 ÷ 有效班次），不用中位数；
4. 只有 1 班车的线路，间隔无定义 → 该线路剔除。

校验：某条真实时刻表 9 班、平均 88 分钟的山区线，用这套算法得到 90 分钟，吻合。

### 4.4 候车不能一刀切

乘客怎么用这条线，决定他等多久：

| 线路类型 | 候车 | 理由 |
|---|---|---|
| 发车间隔 < 20 min（密集） | 间隔 ÷ 2 | 车随到随走，没人看时刻表 |
| 发车间隔 ≥ 20 min（班次疏） | **0（卡点）** | 一天几班的定班车/山区线，乘客必然看时刻表去坐 |
| 高峰专线（10:00–15:00 无车） | 整条剔除 | 中午根本没车，不能当全天可用 |
| 夜间线路 | 剔除 | 口径是白天出行 |

**注**：20 分钟这个阈值是经验值，不是数据推出来的。它的作用是区分"随到随走"和"看表坐车"；
如果场景更偏通勤，可以把阈值调低。

## 5. 抓取

逐跳展开：起点线路 → 候选换乘站 → 换乘站的其他线路。

- **并发不是越大越好**：超过服务端承受能力会返回 503，随后是长时间的退避，总吞吐反而更低。
  实测 8 线程 + 自适应限速（遇 503 减半、成功慢慢回升）比较稳；线程数不要超过 10。
- **一定要有兜底补漏**：主流程跑完后单线程重试失败项，间隔 1 秒以上。
- **错误响应绝不能进缓存**：否则一次失败会被永久"粘住"，下次跑出来还是错的，
  而且和"这条线本来就没数据"长得一模一样，无法区分。写缓存前先判断是不是错误响应。
- **换乘展开失败要当作硬失败**：某个候选换乘站抓取失败时，如果只是记一笔就继续，
  会安静地少算几十个站，而交付物看起来完全正常。要有"失败数不为 0 就重试、仍失败就中止"的检查。

## 6. 出图规则

### 6.1 标注

| 规则 | 起因 |
|---|---|
| 标签不许压站点圆点 | 五个字的站名整块盖住自己的站点，读不出"标的是哪个点" |
| 标签离自己站点有上限（约 11 pt） | 密集区里标签被越推越远，最后"飘到别的站头上" |
| 标签归属分级 | 一刀切"必须离自己最近"会误删本来能标的 |
| 不许上下叠列 | 两个标签上下紧贴会读成一整块 |
| 离画框留边 | 白色描边会压到边框线上 |
| 边界站做空间稀释 | 同一个路口的三座桥会各画一个红圈 |
| 用**渲染后的真实包围盒**做最终去重 | 估算字宽永远不准，尤其是中文字体 |

**实现注意**：偏移量在绘图库里的单位是"点"，碰撞检测用的是像素，两者差一个 dpi/72 的系数。
混用会让预留框整体偏移，出现"判定通过了但实际压上了"。换算必须在同一套单位里做。

### 6.2 版面

| 规则 | 起因 |
|---|---|
| 离散四色 + 离散图例 | 连续渐变的图例和"图上只有 4 种颜色"对不上 |
| 三层标注：片区名 / 大枢纽 / 边界站 | 所有站都标会糊成一片 |
| 比例尺自动找空白区 | 固定位置必然压到某张图的内容 |
| 比例尺长度随图幅自适应 | 一张 3×4 km 的图放 5 km 比例尺，比图还宽 |
| 层级：底色 < 等时面 < 比例尺 < 站点 < 标注 | 比例尺放最上层会盖住站点，放最下层会被标注盖住 |
| 比例尺长度乘 cos(纬度) | 墨卡托在 40°N 会放大 1.3 倍，直接画 5 km 只有 3.8 km |
| 页脚/图例按英寸定位，不按比例 | 画布高矮差别很大，按比例定位会重叠 |
| 页脚单行超宽时自动缩字号 | 长句子在窄画布上会被右边缘切掉 |
| 画布按数据长宽比自适应 | 狭长范围用竖版会留大片空白 |
| 路网底纹只画 ≤900 m 的相邻段 | 跨区段直线会像划痕 |
| 填等时面内部空洞（只填被包围的） | 大居住区中间会留白，看起来像没有覆盖 |

### 6.3 起点标注

起点标注容易被忽略的三个问题：

1. 起点在图边缘时，标注会跑出画框 → "哪边有空间放哪边"；
2. 标注会盖住别的标签 → 先把标注画出来、量出真实包围盒，再让其他标签避让它；
3. 标注会盖住站点圆点 → 半透明，或选一个圆点少的方位。

**改这个函数时不要顺手改它的默认站名**——整段替换函数体很容易把"起点 XXX"的默认值
重置成硬编码的旧站名，结果是所有图的起点都写错。

## 7. 收尾与自检

一次出图至少要跑这些步骤，**改完代码要全部重跑，不能只重画当前那张**：

```
取名 → 起点线路 → 展开换乘 → 补漏 → 计算 → 坐标归并 → 导出 → 底图 → 出图 → 表格 → 矢量
```

**验收清单**：

1. 交付文件齐全（少的常见原因是矢量那步依赖的外部库不存在，而脚本只打印一行提示就继续）
2. CSV / GeoJSON / DBF / SHP 记录数一致
3. 坐标自检打印 OK（如果打印 SKIPPED，说明底图没生成，等于没验）
4. 图上：标签不互压、不压圆点、不被画框裁、比例尺不压内容、起点标注不遮挡
5. 页脚统计数字与表格里的分类计数一致

**测试纪律**：只重跑正在验证的那一个站。全量重跑一张城市图要几分钟，十几张就是半小时。

## 8. 已覆盖的站点类型

用这套流程跑过 20 多个不同类型的起点，结果从 0 站到 2000+ 站，覆盖：

| 类型 | 典型规模 | 会暴露的问题 |
|---|---|---|
| 城区干道站（密集线路） | 800–1300 站 | 标签密度、夜间线剔除、候车÷2 的合理性 |
| 郊区换乘枢纽 | 300–600 站 | 换乘步行、同名站归并 |
| 线路端点站（远郊总站） | 几十–几百站 | **一半方向是死方向**（起点就在终点，下游 0 站） |
| 山区定班线沿线 | 0–40 站 | 发车间隔算错、候车吃掉全部预算 |
| 高峰专线覆盖的站 | — | 中午没车却被当成全天可用 |
| 单线村庄站 | 0 站 | 无时刻表数据 → 图是空的，需要如实说明 |

**通用结论**：

- 班次稀疏的线路，60 分钟预算基本被候车吃掉，图上往往只剩零散几个站——这是模型约定，不是 bug；
- 高速快线会制造"跳跃式"可达，图上是孤立色斑，属于真实情况；
- 一条线只跑高峰的站，任何"全天平均"口径的图都会高估它，必须显式剔除或标注；
- 站点很少时，等时面的插值会显得过大，读图时要理解"色块 = 推断"，不是实测覆盖。

## 9. 已知限制

- 时间是实时到站滚动窗口的常态中位数，不含突发拥堵
- 只算公交 + 步行，不含地铁
- 等时面是站点时间的插值，两站之间的色块是推断值
- 同名站点按 700 m 判定可换乘，可能把"同名不同路口"连上
- 步行只叠加起点周围 1.2 km，不会因为"走过去更快"而新增站点
- 不区分工作日/周末，不区分出发时刻
