# 北京公交 60 分钟可达图 — 全流程与踩坑记录

> 做新图之前先读一遍。**收尾步骤是固定的**（第 7 节），不能只重画当前那一张。

---

## 1. 目标

给定一个公交站，在"最多换乘一次、总耗时 ≤ 60 分钟"约束下，算出所有可达站并出图：

- 总图：等时面（0–15 / 15–30 / 30–45 / 45–60）+ 站点 + 片区名 + 大枢纽 + 边界站
- 核心区放大图：起点周边 8–10 km，逐站标注
- 数据：CSV / GeoJSON / Shapefile（WGS84）

---

## 2. 数据源

MCP：`https://bjbus.jinzihao.me/sse`（SSE + JSON-RPC）

这个 MCP **不在工具列表里**，必须自建 SSE 客户端（`mcp_client.py`）：
GET 拿 `endpoint` → POST JSON-RPC → 响应从 SSE 流回来。

| 工具 | 用途 |
|---|---|
| `query_routes_at_stop` | 某站名经过的线路方向 |
| `query_route_info_by_route_id` | 站点序列 + 经纬度 + 站间距 |
| `query_route_timetable` | **每班车到每站时刻**（核心数据） |

时间算法：
- 乘车 = 同一班车相邻站时刻差，多班次取中位数
- 发车间隔 = 各站到达时刻间隔中位数（跨站汇总，避免短跑班次干扰）
- 候车 = 间隔 ÷ 2

---

## 3. 坐标（最严重的坑）

**数据是 GCJ-02，底图（Esri）是 WGS84**，直接用整体偏东北约 400 m。

自检 `qa_offset.py`：把站点云整体平移，找落在道路亮像素最多的位移。

| | 最优位移 | 结论 |
|---|---|---|
| 原始 | (−79, +40) px ≈ 377 m 东 / 191 m 北 | 有系统偏差 |
| GCJ→WGS 后 | (0, 0) | 对齐 |

同站名还会有 2–16 个坐标（不同港湾/版本，相差 50–270 m），图上会散成多个点。
`fix_coords.py`：260 m 单链接聚类 → 取 **medoid**（真实观测点里最居中的）。
**不要用质心**，质心会落进两港湾之间的地块。

---

## 4. 时间模型

```
总耗时 = 候车₁ + 乘车₁ + 换乘步行 + 候车₂ + 乘车₂ ≤ 60 min
候车   = 发车间隔中位数 ÷ 2
换乘步行 = 90 m + 直线距离 / 1.1 m·s⁻¹（同名站 700 m 内）
步行叠加 = 起点 1.2 km 内站点取 min(公交, 步行)
```

### 4.1 缺失区段按距离补，不能用中位数
滚动窗口里某班车可能只记录了部分站点。用线路中位数补会把
919快 的 61 km 高速段记成 3 分钟（等效 179 km/h）。
→ `cumulative(seg, dists)`，按 `距离 / 14 m·s⁻¹`。

### 4.2 单区段上限 2 小时
`20 <= d <= 7200`。压回 1800 s 会把真实长途段当异常删掉。

### 4.3 服务水平过滤
剔除：`夜*`、`快速直达专线*`（预约式通勤快线，会把可达范围夸大到良乡 34 km）、
观测班次 < 12 的线路。

## 5. 抓取

逐跳展开：起点线路 → 候选换乘站 → 换乘站的其他线路。
**并发过高会返回 503**；`net.Limiter` 自适应限速（起始 6 req/s，503 减半、成功回升），`leg2a` 用 8 线程；`fill_gentle.py` 单线程兜底补漏。
缓存目录被所有工程共享。

## 6. 出图规则

### 6.1 标签

| 规则 | 起因 |
|---|---|
| 不压站点圆点（KDTree） | "木樨园桥东"五字盖住站点 |
| 偏移上限 11 pt（白框 17 pt） | "和平西桥偏到姥姥家" |
| 归属分级：优先离自己最近，比值 <0.72 放弃 | 一刀切会让能标的也不标 |
| 不许上下叠列（x 重叠 >45%、缝 <7 px） | 两个标签上下贴紧像一坨 |
| 离画框 ≥12 px | 白色描边压到边框外 |
| 偏移 >6 px 才加引线且要淡 | 引线多像蛛网 |
| 边界站 1.2 km 稀释 | 三座桥 700 m 内三个红圈 |
| 最终用真实包围盒去重 | 估算字宽不准 |

### 6.2 版面

| 规则 | 起因 |
|---|---|
| 离散四色 + 离散图例 | 渐变图例与图面不符 |
| 三层：片区名 / 白框枢纽 / 红圈边界 | 全标会糊 |
| 比例尺自动找空白区 | 固定位置必压内容 |
| 层级 底色<等时面<比例尺<站点<标注 | 放最上层盖站点，放最下层被压 |
| 比例尺 ×cos(纬度) | 墨卡托 40°N 放大 1.305 倍 |
| 页脚/图例按英寸定位 | 画布高矮差别大 |
| 画布按长宽比自适应 | 横长范围用竖版留大白 |
| 路网连线 ≤900 m 且近可达站 | 跨区段直线像划痕 |
| 填等时面内部空洞 | 大居住区中间留白 |

## 7. 收尾步骤

**两种情况不要混**：

- **新起点**（用 `make_map.py` 建的）：它自己会做完 deliver → shp → 拷贝，不需要动 `finish_all.py`。
- **维护这 6 个老工程**（学院路北口/天通苑/北沙河/沙河/四惠/西苑）：改完代码必须全部重画，再跑 `finish_all.py`。


```powershell
# 批量重画（所有工程，不是只画当前那个）
foreach($d in 各工程目录){ cd $d; python render.py all }

# 一次收尾：deliver → make_shp → 拷贝到交付目录
cd D:\Workspace\bjbus; python finish_all.py
```

新增起点推荐直接用 skill：

```powershell
python D:\Workspace\bjbus\skill\bjbus-reach-map\make_map.py --origin "站名" --out <目录> --shp <名字>
```

## 8. 已知限制

- 常态中位数，不含突发拥堵；等待是间隔的一半，不代表你到站那刻的实际等待
- 只算公交 + 步行，没有地铁
- 等时面是 IDW 插值，站间色块是推断
- 同名站 700 m 内视为可换乘，可能误连
- BRT/高速快线带来跳跃式可达，图上表现为孤立色斑，属真实情况

## 10. 冷启动实测（交给陌生 agent 跑一遍的结论）

`六里桥北里`：461.7 s / 2106 站 / 9 文件 / 坐标自检 dx=0。

耗时：leg2a 83 s，fill_gentle 320 s（最慢，单线程补漏），底图 27 s（12 线程并行，原串行约 4 min），
渲染 11 s，arcpy 12 s。

该测试暴露并已修复的问题：
- 底图瓦片串行下载 → 改 12 线程并行（约 17×）
- 长退避（6/20/60/150 s）导致卡死 → 改短重试 + 自适应限速
- `qa_offset.py` 硬编码窗口、不在拷贝列表 → 改为按底图范围选点，且随工程一起拷贝
- CSV/GeoJSON 把"步行"写成"换乘一次" → 已区分三类
- GeoJSON `name` 是写死的旧站名 → 改为本次站名（`leg1.py` 写 `out_origin.txt`）
- `make_map` 抓取期无输出 → 改为流式打印
- `--shp` 默认值带中文 → 默认 `reach60`
- 文档说"并发 ≤5"与代码 8 线程矛盾 → 统一为"自适应限速，别手动超过 10"

遗留边界：首次跑与复用跑耗时不可比；`make_map` 的渲染器适配靠字符串替换，改文案会直接报错（故意的）。

## 11. 永宁测试（偏远站点）暴露的问题与修复

**两个真 bug**

1. **服务过滤口径不一致**：`leg2b` 只对"直达"检查 `ok`，`leg2a` 选换乘候选时没检查
   → 出现"925 不能直达、却能当第一程"。已修：`leg2a` 跳过 `ok=False` 的 leg-1 记录。
2. **MIN_RUNS=12 把郊区定班车全删了**：延庆 Y11–Y49 一天只有 2–5 班，永宁 17 条线被删 15 条（含 925）。
   已改为 `MIN_RUNS=3`，并可用环境变量 `BJ_MIN_RUNS` 覆盖（12 = 只看城区密集线路）。

**修复后各图站数变化**：永宁 123→366，四惠 1091→1307，西苑 847→1055，沙河 830→833，
六里桥北里 2106→2123；学院路 1013、天通苑 668、北沙河 206 不变。

**取舍**：`MIN_RUNS=3` 会放进"只跑高峰"的线路（观测班次少但间隔看着不大）。
要更保守就设 `BJ_MIN_RUNS=12`；要看乡村定班车就用默认 3。

**另一个坑**：可达范围变大会让**底图范围不够**（图上出现空白条带）。
`make_map.py` 会重取底图，但手工重算时容易忘——重算必须跑 `basemap.py` + `tiles_core.py` 再 `render.py`。

## 12. 密云汽车站测试（远郊端点站）暴露的问题

四个口径问题，都已在文档里写清（代码只改了 3 处）：

**① 端点站有一半方向是死方向**
密云汽车站是 970 / 980快 / 950 / 907 四条线的**终点站**，8 个方向里有 4 个 `origin_idx = n-1`，
下游 0 站。所以"4 条线"实际只有 4 个可用方向，搜索空间比线路数小一半。
→ 判断工作量时看**方向数**，不是线路数。

**② MIN_RUNS 与"候车 = 间隔 ÷ 2"对冲**
`MIN_RUNS=3` 的本意是保留郊区定班车，但一天 3–5 班的线，`estimate_headway` 得到 60–120 min，
候车 30–60 min，剩余预算坐不动两站——**过了过滤也拿不到任何可达站**。
即：乡村定班车在这套模型里系统性不可见，`MIN_RUNS` 放不放宽都改变不了结论。
密云这 4 条线是 72–227 班的高频干线，所以没暴露。（永宁 Y43 能进来是因为它 34 班。）

**③ 远郊图实际测的是"能不能开上高速"**
980快「宁村新桥→太阳宫桥」单段 **66 min**、907「王各庄→望京西」**57 min**，都是真实观测中位数。
结果 980快 到 43.7 min 就断、907 到 49.1 min 就断，整图一个城区站都没有。
物理上正确（密云到东直门全程 120 min），但**远郊图和城区图不可类比**，
读图时要知道"一条高速就把预算耗光了"。

**④ 同线两方向 headway 不同，过滤按方向判定**
970 是 14/10 min、907 是 8/5、950 是 12/11。一条线可能"出城方向通过、进城方向被剔除"。
这不影响结果（只用出城方向），但读 `out_leg1_report.txt` 时会困惑。

**⑤ 换乘门槛已统一**：`leg2a` 的 `MAX_T1=56 min` 与 `leg2b` 原来的 `BUDGET-120=58 min` 不一致，
56–58 min 的站进不了候选池。已统一为 56 min（`BUDGET-240`）。

**⑥ 起点标注会被画布裁掉**：密云汽车站在数据范围最东缘，`origin_callout` 无条件向右偏 26 pt
→ 黄框被切掉一半。已改为"哪边有地方放哪边"，并加 `ha` 对齐。**注意**：改这个函数时别把默认站名
`text=u"起点  XXX"` 一起重置成学院路北口（踩过一次，全图站名都错了）。

## 13. 候车口径与发车间隔（南窖/西沟里/四司/宝盛路口北 测试后确定）

**候车分档**：密集线路（< 20 min）取间隔÷2；班次疏的（≥ 20 min）按卡点 0 分钟；
高峰专线（10–15 点无车）整条剔除；夜间线剔除。可用 `--wait-mode` 覆盖。

**发车间隔必须用带日期的 `query_schedules_by_route_id`**：
- `query_route_timetable` 没有日期，多日数据会合并（Y19 的 4 行 = 2 班/天 × 2 天）
- 同一班车会被重复记录两次（F23：05:15/05:28、07:00/07:15）
- 用平均间隔而不是中位数（中位数只看最密那段）

校验：F23 → 90.2 min（官方时刻表 9 班，均值 88 min）。

**测试纪律**：只重跑被测站点，禁止每次都全量重建。
